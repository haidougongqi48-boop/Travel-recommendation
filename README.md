# Travel-recommendation
旅行先レコメンドAI
https://travel-recommendation-in-japan.streamlit.app

全国1732市区町村の統計データ・土地利用データ・観光来訪者数を組み合わせ、旅行のタイプ（海でのんびり、都会で街歩きなど）に合う地域を推薦するWebアプリです。

修士研究（市区町村別の合計特殊出生率の予測）で整備したデータを、別の目的に活かせないかと考えて個人開発しました。


できること
旅行タイプから探す：「海と自然でのんびり」「山と自然を楽しむ」「電車で行ける観光地」など6つのタイプから選ぶと、おすすめの地域を上位から表示します。
自分で条件を調整する：「海に行きたい」「車で行きたい」などのスライダーで重みを変え、自分好みの条件で地域を探せます。
一番おすすめの地域の説明：上位1件について、各指標の値を表示します。
区の除外：東京23区などの「区」を結果から外すことができます。
工夫した点
1. 数字の組み合わせを「旅行者に分かる指標」に置き換えた

森林や海の面積割合、人口密度、通勤手段、宿泊・飲食業の従業者数などを0〜100に正規化して重み付けし、次のような指標を作りました。

指標	主に使ったデータ
都会度	人口密度、建物用地・道路の割合、電車通勤の割合
自然度	森林・農地・河川湖沼の割合
海度	海水域・海浜の割合
山っぽさ	森林の割合、建物の少なさ、人口密度の低さ
田舎度	森林・農地の割合、自家用車通勤、第1次産業の就業者比率
電車旅向き／車旅向き	通勤手段の割合、鉄道用地・道路の割合
観光・街歩き向き	宿泊・飲食、小売、娯楽業の従業者数、徒歩の割合
2. 「特徴の割に人が少ない地域」を見つけられるようにした

各指標と土地利用データから、その地域の観光来訪者数をランダムフォレストで予測しました（ハイパーパラメータはOptunaで調整）。予測値を「ML観光ポテンシャル」とし、実際の来訪者数から作った「観光人気度」との差を「観光ポテンシャル差」として出しています。この差が大きい地域は、特徴から見れば人が集まってもよいのに実際は少ない、いわば穴場の候補です。

3. データの粒度をそろえた

観光来訪者数のデータは政令市が区ごとに分かれていたため、「札幌市中央区→札幌市」のように市単位に集約してから、統計データと結合しました。

うまくいかなかったこと・課題
1. 都会系の推薦が東京23区で埋まってしまった

「都会で街歩き」で推薦すると、上位20件のほとんどが東京23区になり、推薦としての面白みがありませんでした。23区は人口密度や電車通勤の割合が突出して高く、指標が区同士の比較になってしまうためです。そこで「区を除外する」オプションを追加し、武蔵野市・川崎市・大阪市など、より幅広い地域が出るようにしました。

2. 地域名の表記ゆれで、観光データを結合できない地域があった

「観光ポテンシャル差」の上位に、観光人気度が0の地域（塩竈市、鎌ケ谷市、龍ケ崎市、関ケ原町など）が並びました。調べると、「ケ」と「ヶ」のように地域名の表記が統計データと観光データで異なり、結合できなかった地域の来訪者数を0として扱っていたことが原因と考えられます。結合前に欠損を0で埋めていたため、欠損数の確認でも気づけませんでした。

3. モデルが学習データに合わせすぎている
	決定係数（R²）
学習データ	0.79
テストデータ	0.35

学習データとテストデータで精度に大きな差があり、来訪者数を正確に当てるモデルにはなっていません。そのため、予測値そのものではなく、地域同士を比べるための目安として使っています。

4. 指標の重みを自分の感覚で決めている

「都会度」などの指標の重み（人口密度35%、建物用地30%など）は、根拠となるデータではなく自分の判断で決めています。実際の旅行者の評価と照らし合わせて検証できていないのが課題です。
